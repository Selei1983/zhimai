# 页面与信息架构

## 导航结构

知脉第一版建议采用简单的四区结构：

- 收集箱
- 整理台
- 知识库
- 页面详情

后续再增加：

- 脉图
- 回看
- 设置

## 1. 收集箱

收集箱是所有碎片内容的入口。

### 核心元素

- 快速输入框
- 内容来源
- 原始内容
- 输入时间
- 处理状态
- AI 初步判断

### 状态

- 未处理
- 已分析
- 待确认
- 已写入 Wiki
- 已忽略

## 2. 整理台

整理台是知脉的核心工作区。

它负责把原始内容变成可确认的知识结果。

### 左侧

原始输入内容。

### 中间

AI 整理结果：

- 摘要
- 类型
- 主题
- 关键概念
- 核心观点
- 建议动作

### 右侧

生成后的 Wiki 草稿：

- 标题
- 正文
- 标签
- 关联页面

### 主要操作

- 写入新页面
- 补充已有页面
- 修改草稿
- 重新整理
- 暂存
- 放弃

## 3. 知识库

知识库展示已经沉淀的 Wiki 页面。

### 页面列表字段

- 标题
- 类型
- 标签
- 最近更新
- 关联数量
- 来源数量

### 筛选维度

- 标签
- 页面类型
- 更新时间
- 是否有关联
- 是否有待研究问题

## 4. 页面详情

页面详情是用户阅读和编辑知识的地方。

### 页面结构

- 标题
- 一句话解释
- 正文
- 相关页面
- 来源材料
- 待研究问题
- 更新记录

### 操作

- 编辑
- 追加材料
- 重新整理
- 添加关联
- 标记重点

## 5. 脉图

脉图不是第一版必须功能，但它是知脉未来的重要识别点。

它应该展示：

- 页面之间的关联
- 主题簇
- 孤立页面
- 高频概念
- 近期增长的知识区域

第一版可以先做文本关联，第二版再做可视化。

## 核心数据对象

### Fragment

用户输入的原始碎片。

字段建议：

- id
- content
- source_type
- source_url
- created_at
- status
- ai_summary
- suggested_action

### WikiPage

沉淀后的知识页面。

字段建议：

- id
- title
- slug
- type
- summary
- content_markdown
- tags
- created_at
- updated_at

### Link

知识页面之间的关联。

字段建议：

- from_page_id
- to_page_id
- relation_type
- reason
- confidence

### Source

Wiki 页面引用的原始材料。

字段建议：

- page_id
- fragment_id
- quote
- note
