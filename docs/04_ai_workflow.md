# AI 知识重构流程

## 核心原则

知脉的 AI 不只是总结器。

它应该扮演知识编辑助手，负责把输入内容重构成更稳定的知识形态。

## 输入

用户输入一段原始内容，例如：

- 一段文章摘录
- 一个链接的重点内容
- 一段自己的想法
- 一次对话结论
- 一条产品观察

## 输出

AI 需要输出两类结果：

1. 整理判断  
   帮用户判断这段内容适合怎样处理。

2. Wiki 草稿  
   把内容写成可沉淀的知识页面或页面补丁。

## 步骤 1：内容理解

识别：

- 这段内容讲什么
- 涉及哪些主题
- 属于什么内容类型
- 是否有长期保存价值
- 是否需要拆分

内容类型建议：

- 概念
- 观点
- 方法
- 案例
- 问题
- 经验
- 决策
- 资料

## 步骤 2：知识拆解

从原文中提取：

- 核心概念
- 关键观点
- 论据或案例
- 隐含假设
- 可行动建议
- 需要继续研究的问题

## 步骤 3：知识归属判断

AI 判断这段内容应如何进入知识库：

- 创建新页面
- 补充已有页面
- 拆成多个页面
- 只作为来源材料附加
- 暂不进入 Wiki

## 步骤 4：生成 Wiki 草稿

草稿应避免像普通摘要。

它需要具备：

- 可独立阅读
- 结构清晰
- 语言稳定
- 便于未来追加
- 能和其他页面建立关系

## 步骤 5：关联推荐

AI 推荐相关页面，并说明原因。

关联类型可以包括：

- 补充
- 对比
- 上位主题
- 下位概念
- 案例
- 方法
- 问题

## 步骤 6：用户确认

用户确认后，系统执行写入：

- 新建 Wiki 页面
- 更新已有 Wiki 页面
- 建立页面关联
- 记录来源材料

## AI 输出格式草案

```json
{
  "summary": "这段内容的简要说明",
  "content_type": "观点",
  "topics": ["知识管理", "AI", "个人 Wiki"],
  "suggested_action": "create_page",
  "suggested_title": "知识管理的核心不是收藏，而是重构",
  "key_points": [
    "收藏信息不等于形成知识",
    "知识管理应帮助用户重构认知结构"
  ],
  "wiki_draft": "# 页面标题\n\n## 一句话解释\n\n...",
  "related_pages": [
    {
      "title": "个人知识管理",
      "relation_type": "补充",
      "reason": "该内容解释了知识管理的目标变化"
    }
  ],
  "open_questions": [
    "如何判断一段信息是否值得进入 Wiki？"
  ]
}
```

## 质量标准

AI 生成内容应满足：

- 不夸大原文
- 不编造来源
- 不把碎片写成空泛鸡汤
- 尽量保留用户自己的判断
- 能被未来继续修改和追加
