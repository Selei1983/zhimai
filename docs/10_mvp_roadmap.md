# MVP 推进路线

## 第 0 步：固定产品底稿

目标：

- 明确产品定位
- 明确 MVP 范围
- 明确 AI 整理流程
- 明确 Markdown 存储结构

当前状态：已完成第一版。

## 第 1 步：做 Web MVP

目标：

- 可以输入一段文本
- 可以调用 AI 生成整理结果
- 可以预览 Wiki 草稿
- 可以确认写入个人知识库
- 可以浏览 Wiki 页面

建议先做 Web 应用，因为 Web 是后续浏览器插件和客户端的共同底座。

## 第 2 步：打磨整理台

目标：

- 原文和草稿并排展示
- 显示 AI 判断
- 支持修改草稿
- 支持选择新建或补充页面

这是知脉的核心界面。

## 第 3 步：做浏览器插件

目标：

- 在网页上快速保存选中文本
- 保存当前页面链接和标题
- 支持用户添加一句自己的理解
- 将内容发送到 Web 收集箱
- 在插件里展示处理状态

浏览器插件不承担复杂整理任务，只负责降低收集成本。

## 第 4 步：做知识库浏览

目标：

- 展示 Wiki 页面列表
- 支持搜索
- 支持标签筛选
- 支持查看页面详情
- 展示相关页面

## 第 5 步：加入关联推荐

目标：

- 根据标题、标签、语义相似度推荐相关页面
- 用户确认后写入关联
- 页面详情显示相关知识

## 第 6 步：真实使用测试

用真实材料测试：

- 文章摘录
- 产品想法
- 工作复盘
- 书摘
- 对话总结

判断：

- 生成内容是否值得保留
- 用户是否愿意确认
- 是否出现重复页面
- 是否能找回和复用

## 第 7 步：客户端封装

目标：

- 基于 Web 能力封装桌面客户端
- 支持更好的本地文件读写
- 支持系统级快捷键
- 支持本地知识库同步
- 为离线和隐私模式打基础

## 第一版不急着做

- 移动端 App
- 团队协作
- 图谱动画
- 复杂编辑器
- 完整离线模式
- 公开发布个人 Wiki

## 推荐下一步

下一步建议直接做 Web MVP。

技术形态可以是：

- 一个 Web 整理台
- 一个个人 Wiki 知识库
- 一个 AI 整理接口
- 一个确认写入流程
- 一个后续可对接浏览器插件的收集接口
