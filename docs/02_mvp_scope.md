# 知脉 MVP 范围

## MVP 目标

第一版目标是验证核心工作流：

> 输入碎片 -> AI 整理 -> 生成 Wiki -> 用户确认 -> 建立关联

如果这个闭环成立，知脉就有继续扩展的基础。

## 第一版核心功能

### 1. 收集箱

用户可以输入：

- 文字
- 链接
- 书摘
- 想法
- 对话片段

第一版可以先不处理图片和语音，等文本闭环跑通后再扩展。

### 2. AI 整理

系统对输入内容进行分析，输出：

- 内容摘要
- 主题判断
- 内容类型
- 核心观点
- 可沉淀知识点
- 推荐关联页面
- 建议处理方式

处理方式包括：

- 生成新页面
- 补充已有页面
- 拆成多个知识点
- 标记为待研究问题
- 只保存到收集箱

### 3. Wiki 页面生成

系统生成结构化 Markdown 页面。

页面应具备：

- 清晰标题
- 一句话解释
- 背景上下文
- 核心观点
- 可复用方法
- 相关知识
- 待继续研究的问题

### 4. 用户确认

用户可以在写入知识库前做轻量确认：

- 接受
- 修改
- 改为补充已有页面
- 放弃沉淀

第一版不需要复杂编辑器，但需要支持直接修改 Markdown。

### 5. 知识库浏览

用户可以查看已生成页面。

基础能力包括：

- 页面列表
- 标签筛选
- 关键词搜索
- 相关页面入口

### 6. 关联推荐

系统根据标题、标签、关键词、语义相似度，推荐关联页面。

第一版可以先做推荐关系，不必立刻做复杂图谱可视化。

## 第一版页面

MVP 建议只做四个主页面：

- 收集箱
- 整理台
- 知识库
- 页面详情

可选页面：

- 设置
- 标签管理

## 第一版成功标准

MVP 成功不看页面数量，而看知识重构质量。

建议用这些指标判断：

- 用户输入后是否愿意接受 AI 生成结果
- 生成页面是否比普通摘要更有复用价值
- 系统是否能正确识别适合补充的已有页面
- 用户是否愿意持续把碎片内容丢进来
- 一周后用户是否能从知识库中找回并复用内容

## 暂缓功能

以下功能建议第二阶段再做：

- 浏览器插件
- 微信收藏导入
- 截图 OCR
- 语音输入
- 自动抓取网页全文
- 知识图谱可视化
- 多设备同步
- 分享发布
- 团队空间
